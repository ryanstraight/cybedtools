# cybedtools conformance fixtures

This directory is the parity contract a Python port is built against. It is
committed to the repository and shipped inside the package (`inst/`), so a
port has no dependency on the staged real-framework data under `data/raw/`
or `data/processed/` (both gitignored).

## Files

- `fixture.nt` -- a hand-authored N-Triples graph. Two workforce
  frameworks (`fixture-wf1`, `fixture-wf2`, each with two `cybed:Role`
  organizing units), one pedagogy framework (`fixture-ped1`, one
  organizing unit that is its own top-level statement, with one
  `cybed:Subpoint` and one `cybed:Example` child). It also encodes:
  a statement (`element/fixture-el-role1`) shared by two units across two
  frameworks (`role/fixture-role-2` and `role/fixture-role-4` both link to
  it via `cybed:hasElement`, in addition to their own text); one
  `cybed:UnitRelation` (`fixture-role-1` `requires` `fixture-role-3`);
  non-ASCII text (accented French on the pedagogy unit and its Subpoint,
  N-Triples-escaped as `\uXXXX` per the N-Triples spec, which is why the
  file reads as plain ASCII bytes); and text engineered so
  `framework_similarity()` produces multiple non-zero, differently-tiered
  scores between `fixture-wf1` and `fixture-wf2` (all four cross-framework
  role pairs share the token `network`/`traffic`/`incident*`, at varying
  overlap).
- `mock-release/1.0.0/` -- a release directory in exactly the shape
  `scripts/030-export-release.R` produces: `manifest.json` plus one
  gzipped N-Triples file per framework (`fixture-wf1.nt.gz`,
  `fixture-wf2.nt.gz`, `fixture-ped1.nt.gz`), each framework's
  `sha256`/`sha256_uncompressed` matching the manifest. Used by
  `cybed_fetch()`/`load_graph()` tests via a `file://` URL
  (`options(cybedtools.release_url = ...)`), so no test call reaches the
  network.
- `goldens/*.csv` -- one file per public API function, run against
  `fixture.nt`. Regenerated by `scripts/040-build-goldens.R`; never hand-edited.

## Regenerating

```r
Rscript scripts/040-build-goldens.R
```

Rebuilds `fixture.nt`, the mock release, and every golden CSV from the
in-memory fixture-graph builder in that script (the single source of
truth for the fixture; `fixture.nt` is its serialization).

## The golden format contract (exact, for a Python port)

Every file in `goldens/` is:

- **Encoding**: UTF-8, no byte-order mark.
- **Line endings**: LF (`\n`) only.
- **Header row**: present, exact column names below, in the exact order
  listed (this is also each function's public column order).
- **NA encoding**: an empty field (`,,`), never the literal text `NA`.
- **Numeric rounding**: any similarity `score` column is rounded to
  **10 decimal places** before being written (R: `round(x, 10)`). No other
  numeric columns exist in the current goldens.
- **Sort key**: rows are sorted ascending, exactly as given below, before
  being written. A tie within the sort key is left in whatever order the
  upstream `dplyr` pipeline produced (all current sort keys are unique per
  row, so this does not arise for the shipped fixture).
- **CSV dialect**: comma-delimited, double-quote quoting only where a field
  requires it (a comma, quote, or newline in the value), quotes doubled to
  escape (RFC 4180 / `readr::write_csv()` defaults).

### `framework_metadata.csv`

Columns: `framework` (string, IRI), `name` (string), `jurisdiction`
(string), `sector` (string), `specificity` (string), `framework_slug`
(string). Sort key: `framework`.

### `unit_element_bindings.csv`

Columns: `role` (string, IRI -- the organizing unit), `element` (string,
IRI), `framework_slug` (string, may be empty if the unit has no valid
`cybed:partOf` to a `cybed:Framework`). Sort key: `role`, then `element`.

### `unit_relation_bindings.csv`

Columns: `from_unit` (string, IRI), `relation` (string, may be empty),
`to_unit` (string, IRI), `framework_slug` (string, may be empty). Sort
key: `from_unit`, then `to_unit`, then `relation`.

### `framework_similarity.csv`

Produced by `framework_similarity(rdf, from = "fixture-wf1", to =
"fixture-wf2", n = 5)`. Columns: `from_unit` (string, IRI), `to_unit`
(string, IRI), `score` (numeric in `[0, 1]`, rounded to 10 decimal
places), `strength` (one of `"strong"`, `"moderate"`, `"weak"`, `"none"`),
`rank` (integer, `1..k`, dense per `from_unit`, ties broken by ascending
`to_unit`). Sort key: `from_unit`, then `rank`.

### `cybed_license.csv`

The full result of `cybed_license()` (no argument) against the package's
real shipped `framework_licenses` data (this golden is independent of
`fixture.nt` -- there is no fixture-scale licensing table). Columns and
types match `?framework_licenses`. Sort key: `slug`.

### `framework_summary.csv`

The package's real shipped `framework_summary` data tibble (also
independent of `fixture.nt`, for the same reason: it is precomputed from
the full eleven-framework corpus at package-build time, not derivable from
a small hand fixture). Columns and types match `?framework_summary`. Sort
key: `framework_slug`.

## Deliberately out of scope for these goldens

`cybed_fetch()` and `load_graph()` are network/filesystem-effecting, not
pure query functions over a loaded graph, so they have no golden CSV.
Their conformance test is instead: point `cybedtools.release_url` at
`mock-release/`, fetch, and assert the cached file's hash matches the
manifest (see `tests/testthat/test-cybed-fetch.R`).
